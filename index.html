05 — Setup

Deploy en 5 Minutos

# Instalar Wrangler
npm install -g wrangler

# Login a Cloudflare
wrangler login

# Crear proyecto
wrangler init mi-worker

# Dev local con hot reload
wrangler dev

# Deploy a producción
wrangler deploy

Worker mínimo

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    if (url.pathname === "/webhook" && request.method === "POST") {
      const data = await request.json();
      await env.DB.prepare("INSERT INTO events (data) VALUES (?)")
        .bind(JSON.stringify(data)).run();
      return new Response("OK", { status: 200 });
    }

    return new Response("Not found", { status: 404 });
  },

  async scheduled(event: ScheduledEvent, env: Env): Promise<void> {
    console.log("Cron ejecutado:", event.cron);
  }
};

07 — Trade-offs

Limitaciones Reales

No Python nativo

Beta, no maduro. JS/TS es ciudadano de primera clase.

30s CPU máximo

Plan paid. Para jobs largos necesitas Workflows o server real.

128MB RAM

No para ML pesado ni datasets en memoria.

Sin file system

Todo es fetch/streams. No hay fs.readFile().

KV eventual consistency

Writes tardan ~60s en propagarse globalmente.

D1 es SQLite

Sin JSON queries avanzados ni full-text search nativo.

Vendor lock-in parcial

KV, D1, Durable Objects no son portables a otro provider.

Sin networking privado

No hay VPC ni private subnets. Workers vive en internet público.

⚖️

La jugada inteligente: Workers para el 80% barato y rápido. Un server real (Railway, Fly.io) para el 20% que Workers no puede. No es either/or.
